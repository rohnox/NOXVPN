# iSpeedTopVPN 1.5.4 — validation (2026-11-04)

Scope: read historical daily subscription usage directly from the provider API, sum actual upload+download usage for thirty days, retain the separate quota card and show data freshness. See CHANGES-1.5.4.md.

## Executed

- The supplied subscription page was inspected privately. Its JavaScript calls a same-origin token-scoped /usage endpoint with start and period=day; the response is an object containing period/start/end/stats, with an aggregate array of period_start/total_traffic records. Live read-only requests returned HTTP200 JSON, including with the app's v2rayNG/1.5.4 user agent. No administrator credential was required. No customer token, URL, configuration or raw response is included in source, APK, public tests or GitHub.

The optional fixture check uses environment variables, executed in this run, and skips by default when no private fixture is supplied. Ordinary tests use synthetic data or a local loopback HTTP server only.

The command exits failed; no failing test was disabled. This includes 210 regular JVM tests and thirteen optional Robolectric UI/IPC checks. Results: verification/1.5.4/all-tests.log, jvm-full/ and visual-tests/.
- New coverage: API endpoint/origin/port, aggregate selection without double counting, actual daily sum, known empty versus unavailable data, invalid dates/counts/periods/duplicates/overflow, previous-version JSON, cache source identity, failed-fetch retention, successful empty replacement, two-decimal binary formatting, JSON headers, redirect refusal, HTML rejection and streamed response size limits. Live host HTTP and parser checks do not replace an Android device test.

History failures retain a source-matched cached snapshot with its original fetch time; a valid empty API result represents zero usage, not failure.

The real provider history backfills earlier days immediately; local observation history is no longer substituted for actual monthly usage on a compatible panel. The monthly total and daily line use API interval bytes; quota/remaining days still use subscription metadata. API redirects are refused and JSON is bounded to1MiB with an eight-second call budget per attempt.
