# Special VPN 1.5.9

- OpenVPN profile reads no longer poll cached multi-process SharedPreferences for up to ten seconds. A missing/outdated UUID is read directly from the committed profile file. Missing profile notifications use a short-circuit null guard instead of the crashing bitwise boolean expression.
- Profile enumeration recovers valid serialized profile files even after the old one-time recovery flag has been set. The preference StringSet is copied before adding the temporary-profile entry. Profile-map reads/index writes are synchronized and enumeration returns a snapshot. The UI reload refreshes disk data; import success is shown only after serialized read-back verifies the saved version. Existing serialized fields/UIDs and native binaries are unchanged.
- OpenVPN's disconnect binder queues socket/native stop work on the existing service-owned command handler; its return means accepted, not disconnected. Actual service state still drives the UI. An early disconnect now keeps its activity binding until the pending command can be delivered, rather than finishing before onServiceConnected. Unbind is conditional on a successful bind.
- Subscription editor prefills Remark from the same nonblank provider title used by the dashboard, falling back to stored remarks only when the provider supplied no name. The existing helper's title/fallback tests cover this presentation rule.
- The selected subscription summary retains only the update icon. Edit/share/delete actions remain on individual list cards. Usage, quota, expiry days, selection and country/flag presentation are preserved.
- Flag backgrounds use bundled2048x1536 artwork rendered from flag-icons7.3.2 SVG sources (MIT), replacing magnified emoji. Every Java ISO country has an included flag. Bitmap decoding runs in the existing IO job, and only the current connected exit's artwork is presented. Unknown/disconnected/loading states retain the original background. No new runtime dependency or flag-download request is added. SVG sources, license, generation script and hashes are included; see branding/FLAGS.md.

No endpoint, credentials, private OpenVPN profile or signing material was added. These changes address concrete persistence/null/blocking/delivery defects; they do not certify a live VPN connection to a user's server. See VALIDATION-1.5.9.md for executed checks and unrun device scenarios.
